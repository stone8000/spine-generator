# 流暢原則與 Spine 技巧

這份文件整理兩類知識：一是從 Iron Jaw 錄影量測出的「為什麼順」，二是開發這個工具時用 Spine 4.3.13 runtime 實際量到、但官方手冊沒有寫清楚的行為。每一條都附上證據來源。

---

## 一、Spine runtime 的四個隱藏行為

### 1. 每段曲線被播成 10 條直線

Spine runtime 不是精確計算 Bezier 曲線，而是在每段曲線上取 10 個等分點、用直線連起來（`CurveTimeline.setBezier`，`BEZIER_SIZE = 18`）。

- **後果**：一段 1 秒長的曲線會被切成 10 條 100 ms 的直線（30 fps 下約 3 幀一條）。直線內速度不變、接點處速度突然改變，大動作會出現肉眼難以說明的細微頓挫。量測：一段 1 秒的 8.4 單位擺動，實際播放與真正曲線差 0.05 單位，接點處的加速度尖峰傳到髮尾放大到 2589/s²。
- **對策**：每段曲線不要超過約 0.2 秒（30 fps 下 6 幀），每條直線約 20 ms，60 Hz 螢幕也看不出來。本工具預設 `maxSegment: 0.2`，而且是直接拿「runtime 實際播放的折線」和目標動作比誤差，只在需要的地方加關鍵影格。
- **給手 key 的動畫師**：循環待機不要只在兩個極值放 key。在中間的「通過點」補 key，讓每段 ≤ 6 幀。流暢度檢查會用「長曲線段」提示列出超過 0.34 秒的段。

### 2. Physics 改的是世界座標，局部旋轉讀不到

Spine 4.3 的 Physics 約束直接改骨骼的世界變換矩陣，骨骼 pose 裡的局部 `rotation` 維持原值（量測：髮束局部旋轉變化 0.000°，從世界矩陣反推是 7.07°）。

- **後果**：任何讀骨骼局部旋轉的工具或程式（包括自己寫的匯出、烘焙腳本）都看不到物理效果。
- **本工具的做法**：從世界矩陣把骨骼方向換回父骨座標系，得到包含物理的真實局部角度，再烘成關鍵影格。烘焙結果與即時物理的跟隨延遲相差 ≤ 1 幀。

### 3. 4.3 runtime 只讀新的 constraints 格式

4.3 的 JSON 把 IK、Transform、Path、Physics、Slider 統一放在 `constraints` 陣列裡。4.3 runtime **完全不讀** 4.2 的 `ik`、`transform`、`path`、`physics` 陣列，而且不會報錯。

- **後果**：拿 4.2 匯出的 JSON 給 4.3 runtime，IK 和物理會無聲無息地消失。
- **對策**：版本一定要一致，用 4.3 編輯器重新匯出。本工具遇到舊格式會直接拒絕並說明原因。

### 4. IK 在手臂打直時會「啪」一聲

兩節 IK（上臂＋前臂）的目標點一旦超出手臂總長，手肘會瞬間打直鎖死；在極限附近，目標一點點移動就會讓手肘角度大幅改變。

- **量測**（出拳 130 單位、手臂長 135）：沒有保護時手肘最大每 1/240 秒跳 57°，而且打直到 0°；有保護時最大 16°，手肘始終保持 61° 以上的彎曲。慶祝動作抬手 200 單位：沒有保護時兩隻手臂整段打直，有保護時維持彎曲。
- **對策**：在 Spine 裡設定 IK **softness**（手臂接近打直前開始減速）；或讓 IK 目標不要超出手臂長度。本工具的 `ikGuard` 會讀骨架裡每條兩節 IK 的長度，目標在 85% 長度前照常移動，之後柔性收斂、永遠不超過 95%。

## 二、從 Iron Jaw 量到的流暢原則

（量測方法與數據見 Iron Jaw 動態拆解報告：上一層資料夾的 `IronJaw_動態拆解完整包_2026-10-21.zip` 裡的 `01_報告`，或線上版 https://claude.ai/artifact/M2fZ2WDFh5crhECKfVNA9s 。這裡只整理結論與本工具對應的做法。）

| 原則 | Iron Jaw 實測 | 本工具 |
|---|---|---|
| 一個主節拍 | 兩個角色待機都是 1.99 秒、同時開始；沒中獎的自動旋轉 1.7–2.0 秒 | 格鬥待機預設 2.0 秒；`period` 可調 |
| 只用正弦 | 各部位與正弦吻合度 R² 0.96–0.998，沒有停頓與等速段 | `wave` 以正弦為基礎；檢查器抓等速段與停頓 |
| 對立與錯相 | 雙拳相差約 150°；閃身時頭的上下與左右相差 170° | 預設直接使用量測的相位（60 步循環上的極值位置） |
| 跟隨（follow-through） | 外側髮束擺幅比頭少 25%、無延遲（權重衰減） | 物理烘焙：髮尾晚頭 6–8 步（0.2–0.27 秒），比原作更有層次；檢查器的「全身同步」會抓出沒有跟隨的骨架 |
| 打擊點要硬 | 出拳與 Wild 擴展同一幀觸發，第一幀是 smear | `strike`：位置連續、速度在打擊點刻意斷開；事件 `impact` 放在最遠點 |
| 落定要回彈 | 轉輪停輪過衝 0.11 格、3–4 幀彈回 | `symbol-land` 用同樣的數值 |
| 重複演出要加速 | 輪盤 2.9 → 1.1 → 0.9 秒 | 同一預設加上 `timeScale`（工作室裡的「速度」）產生快版 |
| 畫面不靜止 | 全螢幕演出時角色只壓暗、不暫停 | 循環預設沒有停頓；檢查器把循環裡的停頓列為提示 |

## 三、給在 Spine 編輯器裡手 key 的動畫師

1. **循環的頭尾**：第 0 幀和最後一幀數值相同，**切線也要相同**（檢查器的「循環接縫速度不連續」就是抓這個）。最簡單的做法是讓循環在某個極值點開始，切線自然是平的。
2. **極值放 key、切線拉平**；中間的通過點補 key，每段 ≤ 6 幀（見第一節第 1 點）。
3. **錯開相位**：頭比身體晚 2–3 幀、手再晚 2–3 幀、髮尾再晚。整組 key 在 dopesheet 往後拖即可。檢查器發現 80% 以上的骨骼同一幀到最高點時會提示「全身同步」。
4. **不要用 Linear 曲線**做會動的循環，看起來會像機器。
5. **打擊點**：出拳最遠點的前一段用很重的 ease in（本工具用 quart / quint），之後立刻過衝再回彈，在那一幀放事件給音效。
6. **頭髮、披風**：在 Spine 4.3 加 Physics 約束，循環動畫匯出前開 Warm Up；或用本工具 `hair: "keys"` 把物理烘成 key。
7. **IK 手腳**：設定 softness，或讓目標不要超出長度。
8. **縮放類動作**（呼吸、擠壓伸展）：注意骨骼本身的方向。指向上方的骨骼，局部 X 軸是「垂直」，呼吸的拉長要 key 在 scaleX。本工具會自動判斷。
9. **做完跑一次檢查**：

```bash
node bin/spine-motion.js check 你的檔案.json --loops idle,walk
```
