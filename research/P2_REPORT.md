## A1：肘撐到 90°（關節帶在袖子那側加長、停在手腕，加上每列內點）

**之前。** F3 之後（G2 含單一三角形 [0.3, 3]），lean 網格的肘是 +78 / −64、+62 / −58°，四個方向都停在上臂（袖子）上一條從肘窩外緣拉出去的長扇形三角形。只加長整條關節帶（對稱 3 hw）可以到 96 / 70 / 88 / 62，但 ramp 伸進拳頭：手腕以外的手偏離前臂的剛性運動 12.3–16.5 px（90°）、16.0–21.5 px（120°）。

**為什麼是袖子那側。** 輔助骨分段 ramp 的每半段，是兩個相差 φ（= 彎角的一半）的旋轉在長度 e 上線性混合；離軸 y 的圖，面積比約為 1 − 0.56(1 − cos φ) − sin φ · y/e（φ = 45° 時 y/e ≤ 0.76 才 ≥ 0.3）。量猴子的圖（`$W/a1/profile.py`，正值往軀幹）：左袖在肘上 1 hw 處橫跨 −1.3…+1.7 hw，到 4 hw 處是 +0.1…+2.3 hw；右袖從 −1.5…+1.5 到 −0.3…+2.4 hw：袖子越往上越偏向軀幹。前臂（毛）在手腕前橫跨 3.0–3.4 hw（左 −1.5…+1.9，右 −0.9…+2.1）。上臂有 232 / 229 px 長，肩膀的關節帶只用掉上面 65 / 83 px，袖子那半段可以拉長；前臂那半段不行：手腕在肘下 2.05 / 2.14 hw，再長就彎到拳頭。所以前臂那半段改用網格：多一列、每列加內點，讓肘窩旁的三角形不要從輪廓一路拉到對面。

**改了什麼**（`spinegen/weights.py`、`mesh.py`、`rigbuild.py`、模板）：

- 關節帶可以不對稱：`reach` {upper, lower}（單位 hw，從關節量）。輔助骨仍然在關節上是 100%，兩個半段各自在自己的長度上 ramp（`weights.joint_reach`、`mesh.band_reach`）。對稱時和以前逐位元相同（所有沒設 `reach` 的關節照舊）。
- 關節帶不會跑過往下一個關節（`rigbuild._stop_at_joints`）：肘停在手腕。猴子現在的 2 hw 本來就在手腕前 2–6 px 結束，所以手 0 px。
- 同一層上的兩條關節帶：還是各分一半，但需要得少的那條把剩下的讓給另一條（短的肩膀關節帶讓出袖子給肘）。右肘的袖子那側因此是 3.48 hw（229 − 83 px）。
- `rows` 可以分上下（[3, 4]），`row_points` 讓 lean 網格的列保留 k 個內點，列變成一串約束邊（`mesh._row_chain`）。
- 模板的肘：`reach` 3.5 / 2、`rows` [3, 4]、`row_points` 2。輔助骨仍然分一半（mix 0.5）。

## A2：深蹲 0.10H 不摺疊（膝蓋和腳踝在小腿上重疊、權重串接）

**之前**（`$W/final/monkey_joint`，F1 之後）：spine-core `qa dump --folds`，0.05 / 0.08 / 0.10 / 0.12H 是 1 / 17 / 24 / 31 個摺疊。0.10H 的 24 個：右小腿 14 個在腳踝的關節帶裡（腳踝上方 0.15–0.97 hw），左小腿 8 個、左大腿 2 個在膝蓋的關節帶裡。

**原因，一個一個量**（`$W/a2/`；腳本 `crouch_study.py`、`legprofile.py`、`legcont.py`）：

1. **IK 彎向**：不是原因。每個深度兩個膝蓋都往外（`knees_ok`），蹲完膝彎差 0.15–1.5°。
2. **膝蓋的位置**（左膝為了往外彎，從圖的中線移開 9.3 px）：只有一小部分。改成移髖或移腳踝（膝蓋留在圖的中線上）：0.10H 是 20 / 18 個摺疊（原來 24），而且小腿褲管底會滑 9.7 / 8.2 px（移腳踝連整隻腳都滑 8.2 px），F1 的保證就沒了。左小腿的圖本身就往中線偏：在膝蓋軸上橫跨 −76…+34 px，彎的內側離軸 70–77 px，9.3 px 只是其中一部分。
3. **單邊的腳踝關節帶**（52 / 54 px）：右小腿的圖幾乎都在腳踝軸的外側（腳踝上方 0–100 px 橫跨外 93 … 內 26 px），往外翻出去的褲管在腳踝上方 20–30 px、離軸 87–93 px；蹲下時腳踝合起來的正是外側。沒有輔助骨的 ramp 長 L，離軸 y 的圖面積比約 1 − 0.56(1 − cos D) − sin D · y/L；D ≈ 50°（0.10H）、y ≈ 90 px 要 L ≳ 85 px 才不翻，單邊的關節帶只有 54 px。左腳踝合起來的是外側，那側的圖只有 16–34 px，所以左腳踝沒有摺疊。

## 還沒解決

1. **① 沒有過。** 閘門在 1:1 下判定的「看得到」，比 README 的眼睛嚴格。手量 22° 的地方（22–26°），肘的楔形已經有 24–90 px（右肘往 − 除外），從 6–14° 起每一格都量得到，在表上也看得到。如果放寬 G4，允許 ≤ k·hw² px 的缺口：k = 0.04（52–67 px）時肘會變成 20–32°，大約是手量的數字。但這是對著答案調參數，沒有採用。肩：左邊差 2°，右邊受限於 G2，到 44° 才停。邊緣上的第一批 G4 像素也會隨網格平移幾度（F4）。
2. ~~③ 沒有過（F3 之後）~~：A1 解決，肘 106 / 92 / 108 / 94°。120° 還不能停留（G2 0.86–0.96，3–6 個三角形出界，右肘往 − 1 個摺疊）；要再往上，最便宜的是改圖（肘窩的袖口窄一點、前臂的毛不要伸到 1.9 hw）。
3. **肩膀往外只有 18–60°（新 rig）。** 原因在圖：左肩頂有缺口；左上臂的圖帶著一條軀幹（artreq）；軀幹在手臂下面是深色抹色，沒有畫完。抹色的問題沒有任何閘門在量（不透明，所以不是 G5；和袖子不相關，所以不是 G6b），右肩 +30 / +60° 因此顯示成綠框。需要新的閘門，或在 P3 開成 artreq。
4. **G6b 判斷「誰帶著複本」仍然只看顏色。** F5 之後兩側都讀，但一套顏色、兩色差小於 2.5 ΔE 的身體，兩種情況都會判成底層的殘影：殘影會被抓到，碎片卻會變成關節的限制，而不是 artreq。要用圖案方向（條紋的走向）或參考角色校準（P7）。
5. **lean 網格有很細的三角形**（最小角 0.3°），單一三角形規則最先抓到的常是輪廓上的扇形或小耳朵三角形。肘用每列內點解決（A1）；其他關節帶的列還是只有兩個端點。
6. **腿。**
   - 髖、膝、腳踝的預算不能直接用：掃描時關掉 IK，腳留在 IK 目標上，等於把腳踝拉脫臼。A2 之後膝 82 / 56 / 78 / 44°、腳踝 22 / 48 / 18 / 64°，但這些不是蹲下會用到的姿勢；腿要用 IK 姿勢（蹲、跨步、抬腳）來量，還沒做。
   - 深蹲 0 個摺疊（A2），但 G2 停留閘門在 0.10H 不過（左膝 0.832、右腳踝 0.687，2–3 個三角形 < 0.3）：可以蹲下去、不能停在那裡。
   - 右腳踝的軸心在小腿的圖的內緣：小腿的圖在腳踝上方的中心離軸心往外 37 px。腳踝沒有像肘、膝那樣移到中線（它是 IK 目標，移了會讓腳和褲管滑，A2 量過移腳踝的版本：8.2 px）。
   - 左膝仍然離圖的中線 9.3 px（F1）。A2 量過：改移髖或腳踝，摺疊只少 4–6 個，褲管會滑 8–10 px，所以留在膝蓋。
   - 蹲下時左手和往外擺的大腿之間圍住一塊背景（G5：0.05H 84 px，0.10H 162 + 17 px）。手垂在大腿旁的姿勢本來就會這樣；要嘛手跟著動，要嘛 G5 要分辨「兩個肢體之間」和「身體上的洞」。
7. **P1_FPS_ROBUST 沒過**：60 fps 時 12.07 px，上限 2 px。這是猴子原本的 physics 設定，原封不動帶過來的。
8. **肘、膝移到中線後，原本的動畫是繞新的軸心轉**：右肘移了 20 px，手的位置會差幾 px，還沒有量。IK 的 softness 被 setup 的鬆度限制：左腿拉直後是 0，右腿 3.56 px。
