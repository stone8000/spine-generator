# Spine 4.3 升級指南（Stake Engine web-sdk）

> 結論：新專案採用 **Spine 4.3**。編輯器用 4.3.x，runtime 用 `@esotericsoftware/spine-pixi-v8 4.3.13`，Pixi 升到 `8.22.0`。
> 4.3 本身沒有阻擋性問題，要付的是一次性的升級成本：改 2 個元件、升 4 個 package.json、重新匯出全部 Spine 素材、回歸測試。

查證日期：2026-10-21。對象版本：web-sdk `engineio/web-sdk`（原 `StakeEngine/web-sdk`，GitHub 已轉址）commit `1843d60`（2025-11-28）。

---

## 1. 為什麼用 4.3

| 4.3 帶來的 | 對 Iron Jaw 這類角色的用處 |
|---|---|
| 疊加軌道 `TrackEntry.additive` | 出拳反應播放時，呼吸／擺動可以繼續疊在上面，停留姿勢不會僵住 |
| Sliders | 用一根骨骼控制「蓄力程度」「表情」等混合，不用做一堆過場動畫 |
| Physics 更平滑，runtime 可設 wind / gravity | 頭髮、衣擺晚半拍的二次運動（原作沒有，這是可以超越的地方） |
| `mixInterpolation` 非線性混合 | 待機和反應之間的淡入淡出可以用 ease，不是線性 |
| IK / Physics 的 scaleY 保體積 | 出拳時手臂擠壓伸展不會變瘦 |
| PMA 自動處理 | atlas 的 premultiplied alpha 由 runtime 自動處理，少一個常見的黑邊問題 |

留在 4.2 的唯一好處是 web-sdk 不用改。改動量很小（見第 3 節），所以不值得為此放棄上面這些功能。

---

## 2. 版本對照

| 項目 | 升級前（web-sdk 現況） | 升級後 |
|---|---|---|
| Spine 編輯器 | 範例素材以 4.1.23 / 4.2.x 匯出 | **4.3.x**（2026-09-07 的 4.3.26 為查證時最新） |
| `@esotericsoftware/spine-pixi-v8` | 4.2.74 | **4.3.13** |
| `@esotericsoftware/spine-core` | 4.2.74 | **4.3.13** |
| `pixi.js` | 8.8.1 | **8.22.0**（spine-pixi-v8 4.3.13 要求 `^8.16.0`） |
| `pixi-filters` | 6.1.0 | 不變（peer `pixi.js >=8.0.0-0`） |
| `@barvynkoa/particle-emitter` | 0.0.1 | 不變（peer `pixi.js >=6.0.4 <9.0.0`） |

Spine 規定 **runtime 與匯出資料的 major.minor 必須一致**，所以編輯器 4.3 ↔ runtime 4.3 要一起換。

## 3. 程式改動（共 6 個檔案）

全部包含在 [`web-sdk-spine-4.3.patch`](web-sdk-spine-4.3.patch)；改好的檔案也放在 [`patched-files/`](patched-files/)，路徑與 repo 相同。

### 3.1 `packages/pixi-svelte/src/lib/components/SpineSlot.svelte`（**最重要**）

```diff
 				if (slot) {
-					show = Boolean(slot?.attachment);
+					// Spine 4.3: attachment moved from Slot to its pose
+					show = Boolean(slot.getAppliedPose().attachment);
 				}
```

- 4.3 把 `attachment` 從 `Slot` 移到 slot 的 pose。舊寫法在執行時**不會報錯**，只會讀到 `undefined`，於是 `show` 永遠是 false，**掛在 Spine slot 上的內容全部消失**。
- 範例遊戲有 **30 處、26 個元件**用到它：贏分數字、倍數、免費遊戲次數、Tumble 贏分等。完整清單見 [`SpineSlot使用位置.txt`](SpineSlot使用位置.txt)。
- web-sdk 沒有型別檢查腳本，`pnpm build`（vite build）也不做型別檢查，所以**沒改的話建置會照樣通過**，只有實際玩到才會發現。
- 用 `getAppliedPose()` 而不是 `getPose()`：前者是「實際拿去畫的 pose」，有約束（例如 Slider）改動 slot 時才會和後者不同。

### 3.2 `packages/pixi-svelte/src/lib/components/SpineBone.svelte`

```diff
-	export type Props = Partial<SPINE_PIXI.Bone> & {
+	// Spine 4.3: a bone's local transform (x, y, rotation, scaleX, ...) lives on its pose, not on Bone
+	export type Props = Partial<SPINE_PIXI.BonePose> & {
 ...
 	const bone = spine.skeleton.findBone(props.boneName);
+	const pose = bone?.getPose();
 
-	propsSyncEffect({ props, target: bone, ignore: ['boneName', 'y'] });
+	propsSyncEffect({ props, target: pose, ignore: ['boneName', 'y'] });
 	$effect(() => {
-		if (bone && props.y !== undefined) bone.y = -props.y;
+		if (pose && props.y !== undefined) pose.y = -props.y;
 	});
```

- 4.3 把骨骼的區域變換（x、y、rotation、scaleX…）移到 `bone.getPose()`。舊寫法寫進去不會有任何效果。
- 範例遊戲沒用到，只有 Storybook 的 `SpineBoneControl.stories.svelte` 用到。自己的遊戲若用 `<SpineBone>` 控制骨骼（例如讓角色看向游標），就靠這個修正。

### 3.3 四個 `package.json`

| 檔案 | 改動 |
|---|---|
| `packages/pixi-svelte/package.json` | spine-core、spine-pixi-v8 → 4.3.13；pixi.js → 8.22.0 |
| `packages/components-pixi/package.json` | pixi.js → 8.22.0 |
| `packages/components-storybook/package.json` | pixi.js → 8.22.0 |
| `packages/pixi-svelte-storybook/package.json` | pixi.js → 8.22.0 |

四個要一起改。只改一個的話，pnpm workspace 裡會同時裝兩份 Pixi，`instanceof` 判斷和渲染管線會出錯。

### 3.4 不需要改的地方（已逐一核對 4.3.13 的型別定義）

| 檔案 | 用到的 API | 4.3 狀態 |
|---|---|---|
| `BaseSpineProvider.svelte` | `new Spine(skeletonData)` | 建構子仍接受 `SkeletonData \| SpineOptions \| SpineFromOptions` |
| `SpineProvider.svelte` | `skeletonData.width / height` | 仍存在 |
| `SpineTrack.svelte` | `setAnimation`、`setEmptyAnimation`、`Partial<TrackEntry>` | 仍存在；只移除了 `mixBlend`、`holdPrevious`，範例遊戲沒用 |
| `SpineEventEmitterProvider.svelte` | `beforeUpdateWorldTransforms`、`afterUpdateWorldTransforms` | 仍存在 |
| `assetLoad.ts` | `AtlasAttachmentLoader`、`SkeletonBinary`、`SkeletonJson`、`.scale`、`readSkeletonData` | 不變 |

## 4. 操作步驟

1. **編輯器**：所有動畫師的 Spine 切到 4.3.x（Spine 啟動器可指定版本）。授權方面，年營收 ≥ 50 萬美元的公司須使用 Enterprise。
2. **套用 patch**（在 web-sdk repo 根目錄）：

   ```bash
   git apply --ignore-whitespace web-sdk-spine-4.3.patch
   ```

   如果 repo 已經不是 `1843d60`，patch 對不上時，直接用 `patched-files/` 對照手改。改動只有上面 6 處。
3. **重裝套件**（會重新產生 `pnpm-lock.yaml`，記得一起 commit）：

   ```bash
   pnpm install
   ```

4. **型別檢查**：web-sdk 沒有內建，建議另外跑 svelte-check，讓 4.2 舊寫法在建置前就被抓出來（指令未在本包實測）：

   ```bash
   pnpm dlx svelte-check --workspace packages/pixi-svelte
   ```

5. **重新匯出全部 Spine 素材**（見第 5 節）。
6. **回歸測試**（見第 6 節）。

自己的遊戲程式若有直接呼叫 Spine API，用下面這行找出 4.3 改名或移除的寫法：

```bash
git grep -nE "setToSetupPose|setBonesToSetupPose|setSlotsToSetupPose|\.attachment\b|mixBlend|holdPrevious|getCurrent\(|setCurrent\(|findIkConstraint|findTransformConstraint|findPathConstraint|findPhysicsConstraint|Skeleton\.Physics|Spine\.from|setSkinByName|getAttachmentByName|addAnimationWith|setAnimationWith|setMixWith|getParentMesh|setParentMesh"
```

對照表：

| 4.2 | 4.3 |
|---|---|
| `bone.x / y / rotation / scaleX …` | `bone.getPose().x …`（世界座標用 `bone.getAppliedPose()`） |
| `slot.attachment` | `slot.getAppliedPose().attachment` |
| `skeleton.setToSetupPose()` | `skeleton.setupPose()` |
| `setBonesToSetupPose()` / `setSlotsToSetupPose()` | `setupPoseBones()` / `setupPoseSlots()` |
| `findIkConstraint(name)` 等四個 | `findConstraint(name, IkConstraint)` |
| `ikConstraint.mix` 等約束屬性 | `ikConstraint.getPose().mix` |
| `Skeleton.Physics.update` | `Physics.update`（獨立匯出） |
| `state.setCurrent()` / `getCurrent()` | `setTrack()` / `getTrack()` |
| `TrackEntry.mixBlend` | `TrackEntry.additive` |
| `TrackEntry.holdPrevious` | 已移除 |
| `Spine.from({...})` | `new Spine({...})`（`from` 已標記棄用） |
| `setSkinByName()` / `getAttachmentByName()` | `setSkin()` / `getAttachment()` |
| `addAnimationWith()` / `setAnimationWith()` / `setMixWith()` | `addAnimation()` / `setAnimation()` / `setMix()` |

## 5. 素材重新匯出

- [`素材重匯出清單.csv`](素材重匯出清單.csv) 列出 web-sdk 範例遊戲的全部 **151 個骨架檔**：146 個以 Spine **4.1.23** 匯出、5 個（`bonusButton/2.0/buy_button.json` × 5 款遊戲）以 4.2 匯出，全是 JSON。
- 也就是說，**範例素材本來就和目前的 4.2.74 runtime 版本不一致**，不管升不升級都該重匯出。
- repo 裡**沒有 `.spine` 專案檔**，所以範例素材要這樣處理：
  1. 用 Spine 的 Texture Unpacker 從 `.atlas` + `.png` 還原單張圖片。
  2. 在 4.3 編輯器用 Import Data 匯入原本的 JSON，圖片路徑指到第 1 步的資料夾。
  3. 檢查動畫，再以 4.3 匯出。建議改用二進位 `.skel`：檔案較小、載入較快，`assetLoad.ts` 會依副檔名自動選擇解析器。
- 自己的遊戲直接用 `.spine` 專案檔在 4.3 打開、另存、重匯出即可。**注意：用 4.3 存過的專案檔，4.2 編輯器打不開**，外包和合作美術要同步升級。
- atlas 檔格式不在 4.3 的破壞性變更清單內，可以先沿用；若重新打包，維持原本的 PMA 設定。

## 6. 回歸測試清單

| 項目 | 怎麼測 | 通過標準 |
|---|---|---|
| Slot 掛載內容 | 玩到贏分、倍數、免費遊戲開場／結算、Tumble 贏分（`SpineSlot使用位置.txt` 的 26 個元件） | 數字與文字都有出現，且跟著動畫顯示／隱藏 |
| 骨骼控制 | Storybook `SpineBoneControl` | 拖曳時骨骼跟著動 |
| 全部動畫外觀 | 每個 Spine 動畫至少播一次，與升級前錄影並排比較 | 無破圖、無黑邊、混合時間相同 |
| Physics | 有 physics 的素材（Storybook `SpinePhysics`） | 晃動幅度與升級前相近；循環動畫匯出前開 Warm Up |
| 事件 | 有音效的動畫 | 音效時間點不變 |
| 濾鏡 | 用到 pixi-filters 的畫面 | 外觀不變 |
| 粒子 | 用到 particle-emitter 的畫面 | 版本範圍相容，但仍需實際目視 |
| 效能 | 手機實機，Big Win 與 Bonus 場景 | FPS 與記憶體不比升級前差 |

撤回方式：`git revert` 這次的 commit，並保留 4.2 匯出的素材分支，直到回歸測試通過。
