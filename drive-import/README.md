## 結論

順暢感來自三件事疊在一起：

1. **一個 2 秒的主節拍**：兩個角色的待機都是 1.99 秒循環、同時開始；沒中獎的自動旋轉一轉也是 1.7–2.0 秒。
2. **純正弦曲線驅動的網格待機**：每個部位都只有一個頻率（與正弦吻合度 R² 0.96–0.998），沒有停頓和線性段；身體用帶權重的網格變形（胸口拉伸 7.7%），頭保持剛體；頭髮靠權重衰減擺幅。
3. **只在事件那一幀插入的逐幀反應**：出拳是約 1 秒、帶真實動態模糊的逐幀序列，和 Wild 擴展同一幀觸發；第一幀是全身 smear，用來蓋掉從骨骼待機切過去的接縫；兩個角色錯開 0.17 秒。

轉輪那一側用反拉蓄力（0.17 格）、固定 0.22 秒停輪間隔、過衝回彈（0.11 格）和模糊貼圖把手感補齊；Bonus 的同類演出越來越快（2.9 → 1.1 → 0.9 秒），Big Win 換級用 3–4 幀打擊幀。

## 限制

- **AI 生圖流程**：外部交件的實作結果與還沒解決的問題，見 `10_美術實作` 各份的實作報告。目前只有一套模板（面向右的側面拳擊架式）；「慶祝」動作在頭大手短的角色上，手臂會經過臉前。
- **沒有分析音訊**：本機沒有 ffmpeg，OpenCV 讀不到音軌。「2 秒循環對齊配樂節拍」「音效與停輪同幀」都無法驗證。
- **時間精度約 ±17 ms**：錄影只有 29.74 fps。
- **製作方式屬推論**：「待機是網格動畫、反應是逐幀序列」有數據支撐；但原作實際用的是哪個工具、反應是 AI 生成還是 3D 算圖，無法從錄影證實。
- **web-sdk 升級沒有實際建置執行**：沒有在本機 `pnpm install` 與執行 web-sdk，也沒有用 4.3 runtime 實際播放素材，要靠 `02_Spine4.3升級/升級指南.md` 第 6 節的回歸測試確認。
- **命令列工具要先安裝**：`08_Spine動作工具` 的命令列需要 Node.js 22.18 以上，先 `npm install`（本包不含 node_modules）；工作室 HTML 不用安裝。
- 價格與版本是 2026-10-20／21 查證的資料，之後可能變動。
