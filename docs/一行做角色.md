# 一行做角色：圖層資料夾 → Spine 4.3 動畫

拿到一份角色交件（部件 PNG，可能附 `layers.json`），一行指令就做完：建骨架、套 6 個動作、檢查流暢度、接縫、翻面與關節角度、輸出 Spine 4.3 JSON、報告和預覽 GIF。不用開工作室、不用寫配方。

```bash
spine-motion character 交件資料夾/
```

還沒裝成全域指令的話，在 repo 根目錄用 `node bin/spine-motion.js character 交件資料夾/`（或 `npm run character -- 交件資料夾/`）。

## 交件資料夾要放什麼

| 檔案 | 必要 | 說明 |
|---|---|---|
| 部件 PNG | ✓ | 檔名照 [`生圖交付規格.md`](生圖交付規格.md)（`head.png`、`torso.png`、`arm_front_upper.png`…，13 個必要、3 個選用）。每張同一張畫布、部件留在原位 |
| `layers.json` | | 這張圖的疊圖順序（由後往前），例如後手拳套在胸前。拳套和手上的道具一律排在 `head.png` 後面（疊在頭前面），排錯報告會標 ⚠。`{ "order": ["arm_back_upper.png", …] }` 或直接一個陣列 |
| `joints.json` | | 手動調好的 19 個關節點。沒有就自動猜 |
| `celebrate.params.json` | | 這隻角色的慶祝參數，例如 `{ "params": { "swing": 30 } }` |
| `motion.params.json` | | 任何動作的參數，以動畫名分組，例如 `{ "punch": { "reach": 170 }, "celebrate": { "swing": 30 } }`（也可用 `--params` 指定）；和 `celebrate.params.json` 同時有時，慶祝以後者為準 |
| `budget.json` | | 每個關節的圖撐得住幾度（角度預算），動作轉超過就在報告標 ⚠，寫法見下面 |

`layers.json`、`joints.json`（或 `joints_manual.json`）、`celebrate.params.json`、`motion.params.json`、`budget.json` 放在交件資料夾裡或它的上一層都會自動找到，指令會印出它用了哪些檔。檔名不在模板裡的 PNG（例如 `full.png`、預覽圖）會略過。

## 輸出

預設寫到交件資料夾旁邊的 `<角色名>_spine/`（角色名取資料夾名；資料夾叫 `layers`、`交件`、`圖層` 時取上一層的名字）。

| 檔案 | 用途 |
|---|---|
| `<角色名>.json` + `images/` | Spine 4.3 骨架＋6 個動畫（idle、idle_weave、punch、hit、jump、celebrate）。Spine 編輯器 **Import Data** 匯入，或直接給遊戲載入 |
| `報告.md` | 結論、每個動作的流暢度、接縫、翻面、第一格離原圖、每個關節轉了幾度、關節與骨架檢查、該怎麼修 |
| `預覽.gif` | 6 個動作連著播，用真實圖層合成（需要 Python 3 + Pillow；沒有的話其他檔案照樣產生） |
| `預覽.html` | 離線預覽頁：骨架線、洋蔥皮、軌跡、曲線 |
| `joints.json` | 這次用的關節點，可以改了再用 `--joints` 重跑 |

## 選項

| 選項 | 說明 |
|---|---|
| `-o 資料夾` | 輸出位置 |
| `--name 名稱` | 角色名（骨架與檔名） |
| `--joints 檔案` | 用指定的關節檔 |
| `--celebrate 檔案` | 用指定的慶祝參數 |
| `--budget 檔案` | 用指定的角度預算 |
| `--no-gif` | 不產生 GIF（快很多，約 2 秒） |
| `--bones` | GIF 上畫出骨架線 |

## 看報告、修問題

| 報告寫 | 意思 | 怎麼辦 |
|---|---|---|
| 結論：可以用 | 6 個動作流暢度 ≥ 80、沒有破圖、關節合理 | 直接匯入 Spine |
| 流暢度 < 80 ⚠ | 某根骨在某一秒頓一下，多半是手腳 IK 打直 | 看「說明」欄是哪根骨；腿畫得太直時把膝蓋畫彎一點，或調那個動作的參數 |
| 接縫 ⚠ `肩@0.4s` | 那個關節在那一秒露出背景 | 回去補畫那個關節兩邊的圖層（被遮住的地方也要畫、關節要重疊） |
| 翻面 ⚠ `前手肘反折@0.5s（15 格）` | 手肘或膝蓋折到畫的反方向，或某個部件被鏡像 | 這個動作對這張圖不適用：調那個動作的參數（例如慶祝的 `swing`），或請生圖端畫一張那個姿勢的手 |
| 超出角度預算 ⚠ `前手肘 −84°（預算 30°）` | 動作把關節轉得比 `budget.json` 寫的還多 | 調小那個動作的幅度參數，或補畫讓那個關節撐得住更大角度 |
| 第一格離原圖 ⚠ `後肩 20°` | 待機第 0 格不是畫好的姿勢，遊戲從靜態圖切進待機會跳一下 | 只提醒、不影響結論；預設待機的相位就是這樣，讓第一格貼原圖的版本還在研究 |
| ⚠ 脖子反折／頭頂點太低／肩膀點太低 | 自動猜的關節錯了 | 工作室「從圖層建立角色」拖紅點後「下載關節位置」存成 `joints.json` 放進交件資料夾，或直接改輸出的 `joints.json`，再重跑 |

## 角度預算 `budget.json`

報告的「關節角度」表列出每個動作把每個關節轉離原圖多少度（+ 逆時針、− 順時針，Spine 的 y 向上）。這份圖每個關節撐得住幾度要人看（或用動作研究的 `python -m spinegen.budget` 量），寫成 `budget.json` 放進交件資料夾，下次就會自動檢查：

```json
{ "joints": { "前手肘": { "+": 30, "-": 40 }, "upperArmB": { "+": 45, "-": { "soft": 20, "hard": 30 } } } }
```

關節可以寫報告上的中文名（前肩、前手肘、後膝…）或骨名（`upperArmF`、`foreArmF`、`shinB`…）。每個方向寫度數，或動作研究的 `{ "soft", "hard" }`（用 hard：動作可以經過、不能停在超過的地方）。沒寫的方向不檢查。工具自己不量預算：切塊圖層的關節兩端本來就畫得互相蓋住，單純看有沒有露底量不出極限。

## 範例

```bash
spine-motion character examples/characters/bandit-monkey/layers
spine-motion character examples/characters/boxer/layers --bones
```

大盜猴會自動用上一層的 `joints_manual.json` 和 `celebrate.params.json`；拳擊手全部自動猜，6 個動作都是 100 分。
